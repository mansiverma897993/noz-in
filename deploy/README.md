# AWS validation topology

> To reproduce this project on one machine, use [local/README.md](local/README.md).
> That path needs only Docker and stands up the same pinned SigNoz release with a
> node_exporter sidecar. The two-node topology described here is the environment
> the recorded validation ran in; it is not required to run the tool.

The validation environment uses two EC2 nodes in one availability zone. The
default subnet assigned public addresses, but the project security group has no
public ingress; management uses Systems Manager and application traffic uses
the nodes' private addresses.
The source node runs Prometheus, Grafana, and node_exporter. The destination node
runs the pinned SigNoz stack generated by Foundry. Keeping the stores on separate
hosts prevents ClickHouse and SigNoz query load from perturbing the Prometheus
baseline being used for comparison.

The validation pins Foundry v0.2.13, SigNoz v0.133.0, the SigNoz collector
v0.144.6, Prometheus v3.5.0, Grafana v12.1.0, and node_exporter v1.11.1.
Project-managed images use fixed tags and content digests so a repeated
validation does not silently change under us. Foundry's generated support
services retain the versions recorded in `casting.yaml.lock`.

SigNoz scrapes the source exporters directly every 60 seconds so Prometheus
metric types remain intact. A second, restricted federation job carries only
colon-named recording-rule outputs. The differential harness aligns the two
stores by timestamp before comparing values.

The compose files intentionally publish their application ports on the host.
The AWS security group permits those ports only between the two project nodes;
there is no public ingress. Systems Manager provides shell and port-forwarding
access without SSH. Credentials are generated on their owning node and never
stored in this directory.

Render the destination configuration with the source node's current private
address. The generated file is local inventory and is ignored by version
control:

```sh
SOURCE_PRIVATE_IP=10.0.1.10 deploy/destination/render-casting.sh
foundryctl cast -f deploy/destination/casting.yaml
```

The renderer rejects malformed addresses and publishes through a
mode-restricted temporary file, so an interrupted render cannot leave a partial
configuration.

Before starting the source stack, create the Grafana secret for its container
user. File-backed Compose secrets retain their host ownership:

```sh
install -d -m 0700 deploy/source/secrets
openssl rand -base64 36 > deploy/source/secrets/grafana_admin_password
chown 472:0 deploy/source/secrets/grafana_admin_password
chmod 0400 deploy/source/secrets/grafana_admin_password
```

After the first destination start, initialize the local admin and service-account
key without exposing either value in terminal output:

```sh
sudo deploy/destination/bootstrap.sh
```

The script is idempotent when the stored API key remains valid. Credentials are
written with mode `0600` beneath `/var/lib/promcast` by default.

## Import writer lease

The two-node topology does not provide a distributed lock. Run only one
non-dry-run importer for a given canonical SigNoz target, source namespace, and
logical source identity. Sequential retries are supported after the earlier
process has conclusively stopped; overlapping processes can race even when
they run on different nodes or write artifacts to different directories.

An AWS orchestrator can enforce the contract with a DynamoDB-style lease item
keyed by that tuple (or by a SHA-256 digest of its unambiguous encoding). Safe
lease handling requires conditional acquisition, an unguessable owner token,
periodic conditional renewal, and conditional release. The wrapper must stop
the importer immediately if renewal fails and must keep the lease through
preflight, target mutation, and evidence publication. A DynamoDB TTL attribute
alone is not a lock: expiry/deletion is asynchronous, and the SigNoz API cannot
reject a stale writer with a fencing token. Do not permit takeover merely
because a wall-clock TTL elapsed while the previous process may still be
running. The binary does not create or verify this lease; it is an operator or
orchestrator responsibility.

## Differential validation

Run the comparator from the source node. Prometheus then remains local and the
SigNoz API is reached over the private project security group. Transfer the
service-account key to a mode-restricted source-node file; do not place it in a
command argument or deployment manifest. This reference stack does ingest the
target series through the OpenTelemetry Prometheus receiver, so the command
makes that operator assertion explicitly rather than relying on inference:

```sh
promcast diff /opt/promcast/deploy/source/grafana/dashboards/node-exporter-full.json \
  --source http://127.0.0.1:9090 \
  --target http://DESTINATION_PRIVATE_IP:8080 \
  --target-provenance otel_prometheus_receiver \
  --allow-insecure-http \
  --api-key-file /opt/promcast/secrets/api-key \
  --source-var job=node-exporter \
  --source-var nodename=SOURCE_NODENAME \
  --source-var node=source-node \
  --target-var job=node-exporter \
  --target-var nodename=SOURCE_NODENAME \
  --target-var node=source-node \
  --range 15m \
  --step 1m \
  --timestamp-tolerance 1m \
  --relative-tolerance 0.15 \
  --absolute-tolerance 1e-9 \
  --minimum-coverage 0.8 \
  --workers 4 \
  --migration-report /var/lib/promcast/dashboard/node-exporter-full.report.json \
  --out /var/lib/promcast/differential-report.json
```

Choose a window containing uninterrupted samples on both nodes. A stopped or
newly restarted destination produces an honest `insufficient_overlap` result;
do not lower the coverage threshold to hide an operational gap.
